# Data boundaries

- `raw/`: unchanged, pinned public downloads and SHA-256/source manifest. Ignored by Git. `scripts/source_public_data.py` reconstructs them.
- `normalised/`: separately derived original-text records, provenance, duplicate groups and immutable split allocation. Never overwrite raw sources.
- `reports/`: tracked profiling and verification evidence. Original 15,022-record corpus was not supplied; public replacement contains 7,683 excerpt rows.
- `models/`: local official Laya checkpoint and integrity manifest; generated by `scripts/download_model.py`. No remote inference.
- `voting.sqlite`: ignored SQLite WAL ledger. Back up through SQLite's backup API, or stop writers before copying database/WAL files.
- `run_sources/`: ignored source archives by run UUID. Restore in a separate checkout to reproduce the same code and dependency lock.

Source attribution: [TheTokenFactory SEC financial extraction instructions](https://huggingface.co/datasets/TheTokenFactory/sec-contracts-financial-extraction-instructions), CC BY 4.0, derived from SEC filings. Pinned revision and field mapping appear in the profile. Publisher-generated targets are excluded. These examples have no human-verified votability labels. Authored synthetic challenges live in `tests/fixtures`, never in the demonstration golden dataset.

To import another corpus, create a new database with `VOTING_DB`, explicitly map its fields and repeat profiling/grouping before import. Source records, group assignments, predictions and golden revisions are not silently edited.

## Supervised research additions

- `training/laya_voting_synthetic_500.zip`: supplied, unchanged AI-authored corpus; 300 train / 100 validation / 100 test. These are not expert golden labels. Its README/protocol and prior exposure/duplicate limitations are documented in `reports/LAYA_TRAINING_EVALUATION.md`.
- `experiments/supplied-synthetic-v1/`: append-only model-selection artifacts, frozen code/config/weight hashes, blind predictions committed before answer-key access, per-field metrics/matrices, every failure and learning/automation plots. The held-out supplied split has known duplicate overlap and cannot establish customer accuracy.
- `studies/laya-supervised-v1/`: 1,000-record stratified real-public-data review cohort; immutable group/ID/hash membership, 600 train / 200 validation / 200 frozen test. Currently unlabelled.
- `models/supplied-synthetic-v1/encoder-4ep/`: selected full-encoder Laya fine-tune, experimental and not activated as the public-corpus application model.
- `models/synthetic-smoke-v1/EXCLUDED_FROM_STUDY.json`: historical smoke trained on challenge fixtures; explicitly ineligible for this study. Source challenge fixtures are never used by new training runs.

## ISO15022 hybrid research

- `iso15022_corpus/sources.jsonl`: per-item provenance and SHA-256 commitments. One official illustrative excerpt, 1,100 locally generated partial fixtures, 500 mutations; no production messages.
- `iso15022_corpus/research_sources.json`: authoritative public-source inventory, versions, field mappings, access/licensing limitations.
- `experiments/iso-hybrid-v1/`: frozen pipeline, base/fine native outputs, all-7,683 parser/routing audits, fixed-vocabulary comparison metrics, every failure, reload/fresh-reproduction verification and source-indexed artifact audit. These are research outputs, not verified public-data accuracy.
- `experiments/narrow-v1/`: 300-train/100-validation synthetic three-predicate experiment, membership/hashes, configuration, seed, loss and checkpoint commitment. Original synthetic test was not reused.
- `iso15022-demo.sqlite`: persistent, explicitly synthetic event-history demonstration. Never merge it into the real-public-source or human golden ledger.

Parser fixtures never enter ML training. Public excerpts are not reclassified as SWIFT messages. Unknown fields and unsupported message/profile semantics are preserved for review. Existing source data and the historical blind study remain unchanged.

## Event-level learning qualification

`training-workspace/event-datasets/event-learning-v1/` contains 160 AI-authored,
standards-derived synthetic event chains: 96 train / 32 validation / 16 calibration
/ 16 frozen test, grouped into 20 linguistic families before splitting. These are
640 linked notification/supplement/replacement messages, not real SWIFT traffic.
Original raw messages and review revisions are immutable in the separate
`learning_*` SQLite tables. Existing public-source notices are unchanged.

Rebuild a NEW version after building the local Prowide helper:

```sh
uv run python -m scripts.build_event_learning_corpus --database data/voting.sqlite --output data/training-workspace/event-datasets/NEW_VERSION
```

Training exports are separate from checksum-frozen private answer files.
`event-loop-v1` is a preselected 8-train/4-validation/4-calibration/4-frozen
engineering cohort, not a model-quality benchmark. Models/artifacts are local
and ignored by Git; source generators, tests and reports are versionable.
